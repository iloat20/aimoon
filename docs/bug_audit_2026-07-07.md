### BUG-1　K 线成交量单位三档不一致（差 100×）　✅ 已修复（方案 B）
**文件**：`src/aimoon/adapters/driven/collectors/kline.py`
- L85（档1 `stock_zh_a_hist`）：`volume=float(row.get("成交量",0))` —— akshare 返回单位为 **手**，未换算
- L132（档2 `stock_zh_a_daily`）：`volume=float(row.get("volume",0))` —— 同样为 **手**，未换算
- L191（档3 腾讯）：`volume=vol_f * 100` —— 手 → **股**

**根因**：三档采集的成交量单位不统一。

**影响**：单条 K 线序列来自同一档（优先档1→档2→档3），所以**量比 `volume_ratio_5` 序列内安全**；但**绝对成交量展示 / 跨数据源对比**会随数据源不同差 100×。报告里若展示原始成交量即失真。

**修复（采用方案 B）**：经核实，报告成交量图（`report/index.html`）按 `÷10000` 标注「万手」，且档1/档2 已为「手」，故 **canon 单位应为「手」**。已将档3 腾讯的 `volume=vol_f * 100` 改为 `volume=vol_f`，三档统一为手。AGENTS.md 原"Tencent volume = 手 × 100"约定条目已同步更正。
**回归测试**：`tests/test_tool_chain.py::test_kline_tencent_volume_in_shares_not_x100`（投喂腾讯原始 volume=12345，断言 `bar.volume == 12345.0`，若被 ×100 则失败）。

### BUG-2　财务时序表 EPS 列恒为 "N/A"（数据被丢弃）　✅ 已修复
**文件**：
- `adapters/driven/ai/tools/financial_temporal.py` L48-59（`_serialize`）

**根因**：`FinancialData` 实体确有 `eps: float = 0.0` 字段（`core/domain/entities/financial.py:32`），采集器也填充了它；但 `financial_temporal._serialize` **只序列化** `period/revenue/revenue_yoy/net_profit/net_profit_yoy/roe/operating_cf`，**漏掉 `eps`**。渲染层 `render_financial_temporal` 读 `y.get("eps")` 永远为 `None` → `_fmt_num(None)` → "N/A"。

**回归测试**：`tests/test_tool_chain.py::test_financial_temporal_emits_eps_and_bvps`（断言 `years[0]["eps"]==12.34` 且渲染文本含 "12.34"）。

### BUG-3　LLM 瞬时 HTTP 错误（429/500/503）未重试　✅ 已修复
**文件**：`adapters/driven/ai/pipeline/orchestrator.py`
- L393：`resp.raise_for_status()` 在 HTTP≥400 时抛 `httpx.HTTPStatusError`
- L286：ANALYSIS 重试 `except (httpx.TransportError, OSError, TimeoutError)`

**根因**：`httpx.HTTPStatusError` 是 `httpx.HTTPError` 的子类，**不是** `httpx.TransportError`。重试元组只捕传输层异常，不捕状态码异常。DeepSeek 限流/5xx 时 `HTTPStatusError` 直接穿透重试 `try` → 被外层 broad `except` 接住 → ANALYSIS **静默降级为空**，一次重试机会都没用上。

**影响**：偶发 429/503 直接产出空分析（标 partial），本可重试恢复却没重试，报告质量不稳定。

**修复**：重试元组改为 `except (httpx.TransportError, httpx.HTTPStatusError, OSError, TimeoutError)`，瞬时状态码错误现会被重试至多 3 次。
**回归测试**：`tests/test_orchestrator_wiring.py::test_analysis_retries_on_http_status_error`（mock `_call_llm_with_stream` 前 2 次抛 `HTTPStatusError(429)`、第 3 次成功，断言 `empty_analysis` 非真且 `output` 非空）。
