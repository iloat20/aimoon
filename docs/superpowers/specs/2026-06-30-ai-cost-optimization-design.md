# AI 分析成本优化设计

**日期**：2026-06-30
**目标**：降低单次分析成本，同时保持分析质量

## 背景

当前 AI 分析单次成本约 0.02 元（DeepSeek V3），用户希望降到 0.01 元以下。同时，同一股票的重复分析应复用缓存，避免不必要的 API 调用。

## 方案

### A: 精简提示词

**系统提示词精简**：

当前系统提示词 ~2600 字符，包含大量重复说明。精简到 ~1500 字符：

1. **保留**：4 部分分析框架（业务画像 → 财务诊断 → 交叉验证 → 估值）
2. **保留**：表格格式规则（结论不放表格内）
3. **合并**：数据引用规则的多条细则 → 一句
4. **删除**：输出风格要求中的冗余条目（精炼、数据说话等已隐含在框架中）
5. **删除**：联网搜索相关指令（当前已关闭）

**数据压缩**：

用户数据字典的 key 缩短：

| 原 key | 新 key |
|--------|--------|
| `营收(亿)` | `rev` |
| `营收同比%` | `rev_yoy` |
| `净利润(亿)` | `np` |
| `净利润同比%` | `np_yoy` |
| `ROE%` | `roe` |
| `总资产(亿)` | `ta` |
| `总负债(亿)` | `tl` |
| `经营现金流(亿)` | `ocf` |
| `报告期` | `period` |

其他优化：
- 值为 0 的字段不传
- 社交舆情只传 top5 而非 top20
- K 线摘要保持不变（已精简）

### C: 缓存复用

**缓存策略**：

使用现有 `DiskTtlCache`，namespace 为 `"ai_analysis"`。

缓存 key：`analysis:{symbol}:{date}`

TTL 规则：
- 普通月份：24 小时
- 财报季（1/4/7/10 月）：6 小时
- 手动 `--no-cache`：跳过缓存

**流程变化**：

```
原流程：数据采集 → AI 分析 → 生成报告
新流程：数据采集 → 检查缓存 → [命中] 直接生成报告
                         → [未命中] AI 分析 → 写入缓存 → 生成报告
```

**缓存粒度**：按股票代码 + 日期，同一天内同一股票只分析一次。

## 预估效果

| 指标 | 优化前 | 优化后 |
|------|--------|--------|
| 输入 tokens | ~2800 | ~1500 |
| 输出 tokens | ~8000 | ~8000 |
| 单次成本 | ~0.02 元 | ~0.012 元 |
| 重复分析成本 | ~0.02 元 | 0 元（缓存命中） |
| 分析质量 | 高 | 高（框架不变） |

1. `src/aimoon/adapters/driven/ai/prompts.py` — 精简系统提示词
2. `src/aimoon/adapters/driven/ai/analyzer.py` — 数据压缩 + 缓存逻辑
3. `src/aimoon/adapters/driven/ai/cache.py`（新建）— AI 分析缓存封装
