## 已修复问题

### 1. pyproject.toml 配置错误
- **问题**: `[tool.black]` 和 `[tool.ruff]` 的 `target-version` 设为 `py315`，但项目要求 `>=3.12`
- **修复**: 统一改为 `py312`

### 2. icir_weighter.py — scipy ConstantInputWarning
- **问题**: `spearmanr()` 在输入接近常量时报 `ConstantInputWarning`，刷屏 backtest 日志
- **修复**: 
  - 导入 `ConstantInputWarning`
  - 将 `np.std() == 0` 改为 `< 1e-12` 近零检测
  - 添加 `warnings.catch_warnings()` 抑制剩余警告

### 3. data/spot.py — pandas dateutil 回退警告
- **问题**: `pd.read_json()` 无格式参数导致 "Could not infer format" 警告
- **修复**: 添加 `warnings.catch_warnings()` 过滤

### 4. cache.py — clear() 遗漏 JSON 文件
- **问题**: `clear()` 只删除 `*.pkl` 和 `*.parquet`，遗漏 `*.json`
- **修复**: 添加 `*.json` 到 glob 模式

### 5. 代码风格修复
- 修复 `except (Exception)` → `except Exception`（多文件）
- 修复 `except (OSError)` → `except OSError`（cache.py）
- 修复 `except (ImportError)` → `except ImportError`（cli.py）
- 修复 `except (KeyboardInterrupt)` → `except KeyboardInterrupt`（cli.py）

### 6. 合并分散的 imports
- `entry_rules.py`: 4个独立 import 合并为1个
- `exit_rules.py`: 5个独立 import 合并为1个

### 7. CLI 排序性能优化
- **问题**: `sorted(key=lambda s: hybrid_score(list(s.signals)))` 在排序中 O(n log n) 次调用 `hybrid_score()`
- **修复**: 改用 `s.total_score`（由 screener 预计算），O(1) per 比较
- 移除 `cli.py` 中不再使用的 `hybrid_score` import

### 8. optimizer.py — 冗余 import
- **问题**: 函数内重复 `import pandas as pd`（模块顶部已导入）
- **修复**: 移除内部 import

### 9. _load_screening_data 强制持仓池约束
- **问题**: 持仓池不足时会**回退到全市场数据**，违反"回测必须是持仓池股票"要求
- **修复**: 移除全市场回退，持仓池为空或过滤后 < 5 只时直接退出并给出明确错误提示
- **影响范围**: `backtest` / `optimize` / `schedule` / 默认筛选全部走持仓池
- `_run_train_model` 不受影响（训练可用更广数据源）
- 移除了不再使用的顶层 `get_spot` import

### 10. mootdx_source.py — 000333 取不到数据
- **根因**: `_is_likely_index()` 将 `000xxx` 开头的代码（除 000001/000002）都当成指数跳过
  - 深市主板个股（000333 美的集团、000651 格力电器等）全部被误判
- **修复**: 改用已知指数白名单 `_KNOWN_INDEX_CODES` 精确匹配
  - 白名单: 000016/000300/000688/000852/000905, 399001/399005/399006/399673
  - 000001 排除在白名单外（歧义：上证指数 vs 平安银行，优先让 mootdx 按个股尝试）
- **影响**: 所有深市主板 `000xxx` 股票现在能正常通过 mootdx → Tencent → AKShare 三级兜底

### 11. 因子计算性能优化
- **现状**: 筛查路径串行计算全部 452 因子，回测路径虽有质量过滤但未正确使用
- **修复A — 筛查路径** (`screener.py` `_inject_alpha_signals`):
  - 集成 `get_or_compute_filtered_ids` 质量预过滤（ICIR+Turnover+Correlation，缓存 30 天）
  - 使用 `parallel_compute_factors` 8 线程并行（Numpy 释放 GIL）
  - 保底：质量过滤失败时用 `_select_factor_subset` 分组抽样 100 个
- **修复B — 回测路径** (`ml_integration.py` `compute_alpha_signals`):
  - 修复 BUG：`filtered_ids`（质量过滤结果）未被使用，原代码用全量 registry 二次抽样
  - 改为直接使用 `filtered_ids`，超过 120 个时取前 120（ICIR 降序）
- **粗略效果**: 筛查 452→100(过滤后) 因子，回测 452→200(过滤后)→120(cap) 因子，并行化 8x
  - 首屏运行（需计算质量控制）：约 2x 提升
  - 后续运行（缓存命中）：约 4-5x 提升

### 12. 回测过程审查与优化
**问题A — ML 权重每次重新计算** (`ml_integration.py:336-343`)
- 每次 `get_ml_scores_for_date` 都重复构建 weights 列表+归一化
- **修复**: `init_ml_model` 中预计算归一化权重 `engine._ml_weights`，预测时直接使用

**问题B — fallback 未缓存 None** (`ml_integration.py:293-297`)
- fallback 返回 None 时不写入 cache，导致同日期重复调用
- **修复**: 使用 sentinel `_NULL_SENTINEL` 也缓存 None 结果

**问题C — 无 ML 时候选池过大** (`entry_rules.py:70-71`)
- 无 ML 预筛选时遍历全部 `klines`（可数千只），每 bar 对全部评分
- **修复**: 限制为 `list(klines.keys())[:50]`

**问题D — 首 bar lookahead 风险** (`entry_rules.py:51`)
- `prev_date=None` 时回退到 `bar_date` 获取当日信号，可能包含未来信息
- **修复**: `prev_date is None` 时直接 return，跳过入场

**问题E — TechInd 重复创建** (`portfolio_runner.py` + `ml_integration.py`)
- `_bar_ti_cache` 从未被填充，Phase1/Phase2/Phase4 各自重建 TechInd
- **修复**: `score_stock` 自动填充 `_bar_ti_cache`，同 bar 内复用；每 bar 清空缓存

**问题F — IC 追踪使用前瞻标签** (`portfolio_runner.py:420-443`)
- 前瞻 5 日收益标签计算 IC，存在分析性 lookahead
- **修复**: 添加明确注释标识仅分析用途，禁止用于交易决策

### 13. ML 模型审核与修复
**问题A — Label截断位置不当** (`trainer.py:175` + `data_collection.py`)
- `y.clip(-3.0, 3.0)` 在z-score标准化后执行，极端值已扭曲截面均值/方差
- **修复**: 标准化前裁剪原始百分比 `y.clip(-15.0, 15.0)`，标准化后放宽到 ±4σ

**问题B — ICIR预筛选收益不一致** (`feature_pipeline.py:160-164`)
- 标签使用 open-to-open 收益，但ICIR预筛选fallback用close-to-close
- **修复**: 添加warning日志明确标注 basis mismatch

**问题C — 推理时fillna用截面中位数** (`feature_pipeline.py:413`)
- 单日推理时用当日截面中位数填充NaN，可能引入偏差
- **修复**: 新增 `feature_medians` 参数，推理时传入训练中位数

**问题D — 特征选择使用全量数据** (`data_collection.py:165-178`)
- `select_features_by_ic` 使用全部训练数据评估特征IC，包含"未来"信息
- **修复**: 改为仅使用前60%时间数据（expanding window）

**问题E — 集成权重无最低保护** (`ensemble.py:526-528`)
- Softmax 可能将权重推到极端值（如 0.95/0.05），过拟合近期 IC
- **修复**: 添加 `min_weight=0.20` 最低权重保护+重新归一化

**问题F — 确认无需修复项**
- CV折叠数: 已使用 6-8 folds（`training_loop.py:79/677`），无需调整
- Purged TSCV: 正确实现 purge+embargo，无leakage
- Label时间对齐: 正确使用 T+1 open → T+1+forward_days open

### 14. uv run 回测实战修复

**问题A — `--stocks` 参数被忽略** (`cli.py:_run_backtest`)
- 用户指定 `--stocks "000333,000651,000858"` 但回测仍使用池排序结果
- **修复**: 新增 `_resolve_backtest_stocks()` 检查命令行是否显式传入，过滤评分结果
- **修复2**: `_resolve_backtest_stocks` 中用 `sys.argv` 检测而非 argparse default，避免误判

**问题B — 回测 metrics 属性名不匹配** (`output.py:291-305`)
- `result.total_trades` 不存在 → 始终显示 0；`result.sharpe` 应为 `result.sharpe_ratio`
- **修复**: 统一使用 `EnhancedPortfolioResult` 的实际属性名 `trade_count`/`sharpe_ratio`/`sortino_ratio`

**问题C — mixed date types 错误** (`portfolio_runner.py:73-83`)
- 部分 kline DataFrame 的 index 包含 str 类型日期，混合导致排序失败
- **修复**: 统一 `pd.Timestamp(d)` 转换后再入 all_dates

**问题D — `--no-alpha` 子命令兼容** (`cli.py`)
- `--no-alpha` 是顶层 argument，放在 `backtest` 子命令后会被 reject
- **修复**: 在 backtest 子 parser 也添加 `--no-alpha`

**问题E — 回测 0 trade（小股票池）**
- 仅 2 只股票 + entry_threshold=50 时无法生成入场信号
- **根因**: 入场规则需要评分 >= 50 且排名足够高，2 只股票截面排名无法区分
- **建议**: 至少 10 只以上股票做回测；用 `--top 10` 而非 `--stocks`
