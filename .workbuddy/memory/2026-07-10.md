## 第十二查 bug（共享 httpx client 重复 open）
用户 run `aimoon <code>` 时报 `[guba_html_fetch] RuntimeError: Cannot open a client instance more than once` + `[巨潮资讯] failed ... 同错`。

### 根因（真实 bug，🔴）
- `pipeline.py:45` 创建**一个**共享 `httpx.AsyncClient`，传给 `CompositeStockAnalysisRepository`（含 cninfo + guba）与 AI analyzer；collector 们**并发**执行。
- `cninfo.py:64` 与 `eastmoney_playwright.py:181` 写 `async with (self._http or httpx.AsyncClient(...)) as client:` —— 对共享 client 做 `async with` 会打开即关闭；并发/二次进入已关闭的 client 即抛 `RuntimeError: Cannot open a client instance more than once`（httpx 真实错误）。owner(pipeline 的 `async with`) 才负责关。
- 其余 collector（quote/kline/capital_flow/eastmoney_direct）已用正确模式（`_get_client()` + 仅自管时 `aclose()`），未中招。

### 修复
- `cninfo.py` / `eastmoney_playwright.py`：`async with (self._http or ...)` 改为 `client = self._http or httpx.AsyncClient(...)` + `try:` … `finally: if self._http is None: await client.aclose()`（与 quote.py 一致：共享 client 不关、仅自管时关）。
- `tests/test_collector_baseline.py` 新增 `TestSharedHttpClientLifecycle` 2 测试：真实共享 client 桩网络、连续调用两次，断言 `client.is_closed is False`（修复前第二次 `async with` 抛 RuntimeError → 测试失败，锁定回归）。
